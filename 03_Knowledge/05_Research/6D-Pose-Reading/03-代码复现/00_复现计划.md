## 一、先修正一个预期

你目前读的两篇都是 **benchmark 论文，不是方法论文**。所以：

| 常规理解 | 你的实际情况 |
| --- | --- |
| 复现 = 复现网络结构、训练、指标 | 复现 = 复现**评测流程与指标口径**（VSD / ADD-S / AR 怎么算出来的） |
| 需要 GPU、大数据 | 只要 CPU + 一个数据集 + 官方工具包 |
| 通常很难，新手劝退 | **这反而是新手最好上手的复现目标** |

**结论：不要一上来就复现 FoundationPose。先把「评测怎么算的」跑通，你之后读任何一篇 6D Pose 论文都会有尺子。**

## 二、目标（按难度排序，做完一个再下一个）

### 目标 A：跑通 BOP 评测流程（★ 首选）

| 项 | 内容 |
| --- | --- |
| 产出 | 用官方工具包算出某个方法在**一个数据集**上的 ADD-S / VSD / AR，并与论文里的数字对上 |
| 为什么要做 | 这是阶段一的收口动作。跑通之后，「74.6% 平均 recall」这句话对你才是有意义的 |
| 工具 | **bop_toolkit**（官方评测脚本）：https://github.com/thodan/bop_toolkit |
| 数据 | BOP 已在 HuggingFace 上镜像托管：https://huggingface.co/bop-benchmark —— 每个数据集拆成 `_base`（标注与相机参数）/ `_models`（3D 模型）/ `_test_all`（测试图）/ `_train_pbr`（PBR 渲染训练图）四个包 |
| 起始数据集 | **LM-O**（遮挡版 LineMOD）。理由：规模小、下载快、遮挡问题明确，正好对上 BOP 的核心结论 |
| 验收 | 能说清 VSD 的计算流程；能解释「为什么 LM 和 LM-O 的差距 ≥30%」 |

**动手顺序**（对齐 bop_toolkit README 的五步）：
1. 取数据集 → 2. 跑方法（或用官方提供的示例位姿结果）→ 3. 配置 toolkit → 4. 评估 6D detection 任务 → 5. 评估 detections / instance segmentations

### 目标 B：指标敏感性实验（★ 最有"研究成果"感的一个）

| 项 | 内容 |
| --- | --- |
| 产出 | 一条曲线：**mask 质量（IoU）→ 位姿误差（AR / ADD-S）** |
| 来源 | [05 研究缺口清单](../00-总表整理/05_研究缺口清单.md) 缺口 ⑤ 的最小验证实验 |
| 做法 | 拿到 GT mask，人为退化（膨胀 / 腐蚀 / 随机擦除 / 用 SAM 过分割结果替换），每种退化程度下跑评测，画曲线 |
| 为什么值得做 | MR6D 只给了「2D 分割是瓶颈」这个**排序性结论**，没给定量关系。你把它补出来，就是一个**可写进第一份实验报告**的结果，而且不需要训练任何模型 |
| 依赖 | 目标 A 必须先跑通 |
