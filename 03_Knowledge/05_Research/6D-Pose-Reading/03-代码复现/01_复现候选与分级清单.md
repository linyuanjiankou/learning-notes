# 01 复现候选与分级清单

> 建立：2026-10-26 ｜ 排序口径：**可复现程度 × 复现后可视化程度**，不是论文影响力。
> 硬件前提：**RTX 5070 Ti（16 GB，Blackwell / sm_120）+ 核显 CPU**。这一条是硬约束 —— 很多老仓库钉在 CUDA 11 上，在 50 系卡上装不上。
> 与 [00_复现计划](00_复现计划.md) 的关系：那份是「阶段四怎么走」的方法论；本文件是「具体挑哪几篇、按什么顺序、每篇能出什么图」。
>
> ⚠️ 核实边界：本会话 **GitHub 不可达**（连接重置）、项目页部分超时。因此「仓库存在 / 有权重 / 有 demo」这类只写 arXiv 摘要或注释里能确认的；**具体依赖版本、显存占用、跑通命令一律 `[需核实]`**，回 Code 会话用 `git clone` 现场确认。

## 一、两条轴怎么打分

| 轴 | 看什么 | 加分项 | 减分项 |
| --- | --- | --- | --- |
| **可复现程度** | 代码 + 权重 + 数据 + 依赖四样是否齐全，能不能不训练就出结果 | 官方代码、官方权重、纯 CPU、数据集小、依赖少 | 需训练、权重不公开、需要自写 CUDA 扩展、老框架（TF1 / Caffe / MXNet） |
| **可视化程度** | 能不能出一张**能放进 meeting 的图**，而不是一个数字 | 位姿 overlay、render-and-compare 对照图、中间表示热图、PR 曲线 | 只有一张指标表 |

两项都高 → 排在前面。**先出图，再谈理解**：一张自己跑出来的 PR 曲线，比读十篇方法论文更能建立「尺子」。

### 关于你这张卡（5070 Ti）的先验判断

50 系是 Blackwell（计算能力 sm_120），只认 **CUDA 12.8 及以上**的构建；而不少 6D pose 仓库的 `environment.yml` 还钉在 CUDA 11.x / PyTorch 1.x（`[需核实:逐仓库确认]`）。实际后果是：**代码写得再全，环境装不上就等于不可复现**。所以本表里凡是「需要编译 CUDA 扩展」或「老框架」的，档位都往下压了一档，并把风险单独列一列。

若确实要跑老仓库，两条路：① 用 Docker（基础镜像带对应 CUDA），靠容器规避宿主驱动差异；② 找社区的新版复现（但那就不是原文实现了，笔记里要写清是二手复现）。

## 三、复现卡片

### 卡片 1 ｜ BOP 评测链（S 级，先做这个）

**定位**：不是网络，是尺子。跑通后你读任何一篇 6D pose 论文都有判断力。

**为什么排第一**：唯一纯 CPU、唯一不需要权重、唯一不依赖 CUDA 生态的候选；而且它正好是 [00_复现计划](00_复现计划.md) 目标 A 与 idea-01 的共同前置。

- **代码**：bop_toolkit（官方评测脚本，[00_复现计划](00_复现计划.md) 已写明五步流程）
- **数据**：LM-O。BOP 官方 + HuggingFace 镜像（`bop-benchmark`，拆成 `_base` / `_models` / `_test_all` / `_train_pbr` 四包，见复现计划）
- **最小路径**：取 LM-O → 用官方示例位姿结果（不用自己跑网络）→ 配 toolkit → 评估 6D detection → 评估 instance segmentation
- **能复现的图**：
  - 6 个数据集上的 **AR 条形图**（对上 BOP 论文里 Vidal-18 = 74.6% 那张）→ 验收：数字能对上，误差来自阈值设置
  - **recall vs VSD 阈值曲线** → 验收：能解释为什么换阈值排名会变
- **卡点**：BOP 论文与 bop_toolkit 版本口径要对齐（VSD 的 τ 与 δ 默认值）；HuggingFace 下载量大，注意磁盘
- **和你的线的关系**：直接落地 T8（metrics 源码线）；是 idea-01（mask 退化 → 位姿误差）的前置

### 卡片 2 ｜ FoundationPose（A 级，可视化最讨喜）

**定位**：一张图或一段视频进去，输出带 mesh 的位姿 overlay。CVPR 2024 Highlight。

**为什么排 A**：官方权重 + 官方 demo，出图质量高；缺点是需要编译 CUDA 扩展，50 系卡上是主要风险点。

- **代码/项目页**：[nvlabs.github.io/FoundationPose](https://nvlabs.github.io/FoundationPose/)（arXiv 摘要给的正式入口）
- **数据**：自带 demo 样例（单图 / 视频）；也可接 YCB-V、LM-O
- **能复现的图**：位姿 overlay、逐帧跟踪、render-and-compare 对照
- **卡点**：① 需要 CUDA 编译（自定义扩展 + 可微渲染依赖，官方用到 nvdiffrast `[需核实:版本]`）→ **Blackwell 上大概率要重编并改版本**；② 显存峰值 `[需核实]`；③ 依赖 PyTorch / CUDA 组合较老
- **建议**：**先做卡片 1，再做这张**。因为跑通后你能用 bop_toolkit 给它的输出打分，而不是只看 overlay 好不好看。

### 卡片 3 ｜ MegaPose（A 级，最能把「精化」讲清楚）

**定位**：render-and-compare 的教科书实现 —— 渲染一版、和观测比、算差值、更新位姿。

- **代码/权重**：[megapose6d.github.io](https://megapose6d.github.io/)（arXiv 明确写「代码、数据集、训练模型均在此」）
- **能复现的图**：**四联图**（原图 / 当前位姿渲染 / 差值图 / 迭代后叠加），这类图在 meeting 上比指标表有说服力
- **卡点**：老版 PyTorch + 编译依赖；首次跑要下模型权重
- **和你的线的关系**：`render-and-compare` 是理解 FoundationPose / Any6D 的公共语言，读这篇等于一次拿到三篇的钥匙

### 卡片 4 ｜ SAM-6D（A 级，接你的分割-位姿主线）

**定位**：SAM 出候选掩码 → 匹配 → 位姿。**它把「分割」和「位姿」显式分成两个子网络**。

- **代码**：[JiehongLin/SAM-6D](https://github.com/JiehongLin/SAM-6D)（arXiv 注释里给的官方地址）
- **能复现的图**：分割掩码 + 位姿叠加、点匹配连线
- **为什么和你的线有关**：你的 idea-01 是「分割质量 → 位姿误差」，这篇是少数把两段拆开实现的代码；把它当**被测对象**，比当论文读有用
- **卡点**：SAM 权重 + PyTorch 版本；`[需核实:显存需求]`

### 卡片 5 ｜ GDRNPP（B 级，中间表示最值得看）

**定位**：BOP 榜单连续两年的冠军线。真正值钱的不是分数，是它的**中间表示**。

- **代码**：[shanice-l/gdrnpp_bop2022](https://github.com/shanice-l/gdrnpp_bop2022)（arXiv 注释给的官方地址），官方模型可用
- **能复现的图**：**M2D 坐标图**（每个像素回归到的 3D 点坐标，可着色成 XYZ→RGB）+ **SCF 表面区域热图**。这两张是「网络到底学到了什么」最直观的证据
- **卡点**：依赖多、数据全量大；训练重，建议**只用官方权重做推理 + 可视化中间量**，不训
- **建议**：等你读完 P0 里的 #38/#40 再来，那时看 M2D 会有共鸣

### 卡片 6 ｜ PVNet（B 级，理解「投票」最快的入口）

- **代码**：[zju-3dv.github.io/pvnet](https://zju-3dv.github.io/pvnet/)
- **能复现的图**：像素级**单位向量场**（箭头图）+ 关键点热图 + RANSAC 投票分布
- **代价**：要训练（LM-O 规模，16 GB 可承受），老 PyTorch 可能要打补丁
- **为什么值得**：PoseCNN 的「中心投票」和 PVNet 的「关键点投票」是同一思想的两代，对比这两张向量场图，比读两篇 method 节快

### 不建议现在动的两篇

**PoseCNN**（TF1/Caffe 时代）与 **DeepIM**（MXNet）—— 代码能看，但在 Blackwell 上基本跑不起来。它们的价值是**读**（PoseCNN 你已经读完并出卡了），不是跑。若一定要跑，找第三方 PyTorch 复现，但那就不叫复现原文了。

## 五、术语投喂协议（你说的那个用法）

**你做什么**：看到不懂的词，发我「词 + 它在哪句话里」，不用解释。

**我做什么**：
1. 判它是**领域通识**（→ 一句话解释，不发论文）、**某篇论文的具体设计**（→ 给源头论文 + 该读哪一节），还是**你的笔记与原文冲突**（→ 提出来记进 [11_问题与待办](../00-总表整理/11_问题与待办.md)）。
2. 给你 **arXiv 链接 + 定位到节**，不甩整篇；需要时我读那一节再讲。
3. 判断「值不值得读全文」，给结论而不是把选择权推回给你。

**关于 PDF**：本 vault 不放 PDF（[CLAUDE.md §十一](../CLAUDE.md)）。想要本地文件的话，在 Code 会话里用 `zotero-cli add doi|url` 入库顺手落盘，比放进这个文件夹干净。
