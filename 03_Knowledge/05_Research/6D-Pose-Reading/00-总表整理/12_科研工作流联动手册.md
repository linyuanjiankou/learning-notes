# 12 科研工作流联动手册

> 建立：2026-10-26 ｜ 目的：把 vault 里已经写死的约定，和本机安装的四组技能（`research-workflow` / `pose-domain` / `ecc-slim` / `anthropic-skills`）焊在一起，让「读一篇论文」变成一条**可执行、可验收、可回填**的流水线。
> 项目入口是根目录 [CLAUDE.md](../CLAUDE.md)；本文件是它的详细版，只讲**怎么对接**，不重复领域知识。

## 一、一句话对应关系

你这套 vault 已经把工作流的抽象纪律写成了具体表格；技能组补的是**你还没有的三个机械部件**：检索、读原文、验收门禁。

| 技能 | 它提供的 | vault 里已有的对应物 | 关系 |
| --- | --- | --- | --- |
| `research-workflow` 验收清单 | 检索/笔记/监测/代码四链的交付门禁 | [00_阅读看板](00_阅读看板.md) 两条铁律 + 各表填写要求 | **同构**，可互相校验：技能每条验收都能在本 vault 找到落点 |
| `pose-claim-check` | 指标数字四件套 + 「性能好」打回 + 主语检查 | [09_识别信号表](09_识别信号表与卡点自救.md)「实验看不懂」行、[03 表](03_数据集与指标表.md) 的阈值标注 | 技能是你那条规则**可执行版**，含你踩过的 YCB-Video / LM-O 口径陷阱 |
| `6d-pose-domain` | 数据集手册、指标词典、方法族谱、阅读字段清单 | [03 表](03_数据集与指标表.md)、[10_术语表](10_术语表.md)、[07 模板](07_单篇结构化笔记模板.md) | **外部参考**，只用于定位查缺；登记进表必须标 `[外部参考，待核实]` |
| `obsidian-paper-note` | 定位条目 → 取原文 → 按模板抽取 → 选落点 → 回填 | [07 模板](07_单篇结构化笔记模板.md) + 回填链 | 技能的 Step 5 已内置**本项目的 7 处回填清单** |
| `academic-paper-search` | 6 步检索链 + 去重 + Zotero 入库 | 无（纯缺口） | **新增能力**，对应待办 T7 |
| `deepxiv-cli` / `zotero-cli` | 读原文 / 读写库 | 无（纯缺口） | **新增能力**，但只能在 Code 会话跑 |
| `research-paper-monitor` | 领域监测 + 日报 | [00_阅读看板](00_阅读看板.md) 第五节的节奏 | 可选增强，把「每周日手动筛」变成自动候选 |

## 二、四条链在本项目的落点

### 链路 1：检索链（新增，对应 T7）

`academic-paper-search` 的 6 步 → 本项目的落点：

| 步骤 | 技能动作 | 本项目落点 |
| --- | --- | --- |
| 1–2 | 多库检索 + 跨平台检索，合并去重 | 候选清单先对照 [00_阅读看板](00_阅读看板.md) 现有 46 篇去重，**不盲目入池** |
| 3 | deepxiv 取骨架（abstract + 章节清单） | 只用来判 P0/P1，**不读全文**。判定标准见看板 §二 的「2026-10-26 优先级重排说明」 |
| 4 | 监测配置 | 默认「未启用」；要开就建成 scheduled task（见链路 4） |
| 5–6 | Zotero 入库，集合复用优先 | Zotero 集合名与看板阶段对齐（`6D-Pose/阶段一` … `阶段六`），这样矩阵 ID 与集合能互相定位 |

**入池前置判定（技能里没有，必须人工做）**：这篇是**方法论文**还是**基准/数据集论文**？这是 [09 表](09_识别信号表与卡点自救.md) 第三节记下的教训 —— benchmark 只给赛道和尺子，不给跑法。

### 链路 2：笔记链（主用）

`obsidian-paper-note` 五步 → 本项目参数：

| 步骤 | 本项目怎么跑 |
| --- | --- |
| Step 1 定位 | `zotero-cli --json search "<标题>" --limit 5 --detail keys_only`，多候选**必须让我确认** |
| Step 2 元信息 | `get metadata` / `get children` / `path <附件key>`；`outline` 不可用，页数从 `read` 输出的 `Total pages in PDF: N` 读 |
| Step 3 读正文 | 泛读：`--brief` → `--head` → `Introduction` / `Conclusion`；精读：按 [07 模板](07_单篇结构化笔记模板.md) 的节取 `Introduction` / `Method` / `Experiment` / `Discussion` / `Limitation`。第 5 级全文与读 PDF **先问我** |
| Step 4 抽取 | 强制过 `pose-claim-check` 三条规则；优点必须写成「在 XX 数据集、XX 指标、XX 口径、与 XX 比，提升 XX」 |
| Step 5 落点回填 | 笔记落 [01-笔记](../01-笔记/)，然后按 [CLAUDE.md §五](../CLAUDE.md) 的 8 处清单回填（1–3 强制） |

**格式优先级**：项目模板（6 正文节 + 3 补充节）> 技能默认模板。技能的「6 问 + 3 补充」只是默认值，**不覆盖** 07 模板。

### 链路 3：代码链（对应 T8、复现目标 A–C）

| 复现目标 | 技能 | 验收 |
| --- | --- | --- |
| A：bop_toolkit + LM-O 跑通评测 | `code-reviewer`（agent）+ `verification-loop` | 能说清 VSD 计算流程；能解释「为什么 LM 与 LM-O 差距 ≥30%」 |
| B：mask 退化 → 位姿误差曲线（idea-01） | 同上，重点是可复现随机种子 + 退化参数写死在配置里 | 曲线能画出来，且 GT mask 上界与论文数字对得上 |
| C：MR6D unseen pipeline | 同上 | 依赖 FoundationPose 原文先读完（阶段五 P0） |

代码与数据**不进本文件夹**，`03-代码复现/` 只写记录。详见 [00_复现计划](../03-代码复现/00_复现计划.md)。

### 链路 4：监测链（可选，需要先决定）

`research-paper-monitor` → scheduled task。建议参数：每天 08:00、key 用 `6D pose estimation`、`self-occlusion`、`pose uncertainty`、`BOP benchmark`；产出先落一个待定目录（建议 `00-总表整理/inbox_日报/`，**不新建顶层目录**），我确认后你才把它们搬进看板对应阶段。

> 注意：监测脚本依赖本机 CLI，只在 Code 会话可跑；本应用里只能建 scheduled task 壳，不能替它执行。

## 四、一次会话的推荐开场

三种最常用，直接抄：

**A. 今天读什么**
> 读 `CLAUDE.md` 和 `00_阅读看板.md`，按重排后的 P0 告诉我今天该读哪一篇、为什么是它而不是下一篇，然后给我 20 分钟略读需要看的 5 个位置。

**B. 帮我记这一篇**
> 泛读 `<标题>`，走 `obsidian-paper-note` 泛读模式；抽完先过 `pose-claim-check`，再把要回填的 8 处列给我确认，**确认后再写文件**。

**C. 帮我筛新论文**
> 按 T7 筛 2024–2026 的 6D pose 论文（主题偏自遮挡 / 分割-位姿 / 不确定性 / novel object），每篇给我：年份、venue、属于哪条缺口线、建议快读还是精读。**先只出清单，不要入池、不要入库。**

## 五、交付前验收清单（合并版）

任何一篇笔记 / 一次表格更新，交付前逐条过：

- [ ] 6 正文节 + 3 补充节齐全（泛读），或 07 全模板齐全（精读）
- [ ] 自己的批判 ≥ 2 条，含至少 1 条「论文未说明」
- [ ] 全文无遗留 `[需核实:…]`（或明确说明为何保留）
- [ ] 每个指标数字四件套齐全：数据集 + 指标 + 阈值/AUC 口径 + 对比对象
- [ ] 没有「性能好 / 效果优 / 精度更高」这类无数字结论
- [ ] benchmark 论文的数字，主语写的是被评测方法而不是作者
- [ ] 回填 1–3 必做：笔记卡、`00_笔记索引`、`00_阅读看板`（状态 + 快照 + 一句话结论）
- [ ] 回填 4–8 按需：01 矩阵 / 02 演进链 / 03 指标表 / 04 线索表 / 05 缺口清单
- [ ] 每条登记都带来源笔记链接
- [ ] 外部参考填进来的格子已标 `[外部参考，待核实]`
