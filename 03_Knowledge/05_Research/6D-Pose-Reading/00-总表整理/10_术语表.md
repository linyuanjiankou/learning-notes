| texture-mapped 3D object model | 带纹理映射的 3D 物体模型 | 3D mesh + 表面纹理。用途：渲染训练数据、提取特征、建立 2D-3D 对应、计算 ADD | 9.25 问题记录 |

| point-pair features (PPF) | 点对特征 | 用一对 3D 点及其法线构造的几何描述子。匹配模型与场景点对，投票生成 6D 位姿假设，适合 RGB-D / 点云 | 9.25 问题记录 |

| feature point | 特征点 ⭐ | 图像 / 点云中可被稳定检测与匹配的局部点（角点、边缘交点、纹理显著点）。传统 6D 位姿方法靠它建立 2D-3D 对应；无纹理物体没有它，所以这类方法失效 | 10.5 问题记录（词）｜解释为本次补注 |

## B. 具身智能 / VLA（17 条）

> 集中在 π₀.₅ 与 Embodied AI 技术路线两轮笔记里。解释以 π₀.₅ 为参照对象。

| 术语 | 中文 | 解释 | 出处 |
| --- | --- | --- | --- |
| 低层动作 chunk | low-level action chunk | 模型不是每步只输出一个动作，而是一次输出未来一小段动作序列。π₀.₅ 一次输出 50 步（约 1 秒，50 Hz）。「低层」指具体控制指令：关节目标、末端执行器目标位姿、夹爪、躯干升降、基座速度 | 9.18 问题记录 |
| 预训练阶段（离散 token + 自回归 next-token prediction + FAST action tokenizer） | π₀.₅ 第一阶段训练 | 把图像、语言、检测框、动作统一成 token 序列，用「给定前面的 token，预测下一个」的自回归方式训练。连续动作经 FAST tokenizer 压缩、量化成离散 token，从而能像文本一样参与大规模预训练 | 9.18 问题记录 |
| Action Expert | 动作专家 | Transformer 中专门生成动作的一组专家权重，参数比 VLM 主干小。接收带噪动作 token，输出 flow matching 的向量场。与主干通过 self-attention 交互，但信息基本单向：VLM → Action Expert | 9.18 问题记录 |
| Flow Matching | 流匹配 | 生成模型，学习从随机噪声逐步流向真实动作的「速度场」。训练：给真实动作加噪声，学如何从噪声恢复；推理：从噪声出发沿学到的方向积分几步，得连续动作序列。比 diffusion 更直接、更高效 | 9.18、9.21 问题记录 |
| 具身 Chain-of-Thought | embodied CoT | 让机器人先「想一下下一步做什么」再输出动作。π₀.₅ 先根据观测与总任务预测高层子任务（如「拿起盘子」），再据此预测低层动作 chunk。类似语言模型的思维链，但高层推理频率低于低层动作推理 | 9.18 问题记录 |
| End-to-End Robot Control | 端到端机器人控制 | 从传感器输入直接学控制指令，中间不手工设计检测、6D Pose、任务规划、运动规划等模块。π₀.₅ 的高层与低层由同一模型学习，低层直接输出目标位姿与速度，无额外轨迹规划或碰撞检测 | 9.18 问题记录 |
| Hybrid Multi-modal Examples | 混合多模态训练样本 | 训练样本格式不单一：图像观察、语言命令、物体检测、语义子任务预测、低层动作、Web 问答等。不同格式统一成 token 序列，让同一个模型一起学 | 9.18 问题记录 |
| Training Recipes | 训练配方 / 课程表 | 数据怎么混合、分几个阶段训练、用什么损失、动作怎么表示、超参数怎么设。π₀.₅ 的核心贡献之一就是这套共训练配方，**而不只是模型结构** | 9.18 问题记录 |
| Dexterous Manipulation Skills | 灵巧操作技能 | 需要精细、多自由度、协调控制的任务：铺床、餐具入水槽、衣物入洗衣篮、开关抽屉、整理枕头、擦洒出物、挂毛巾。π₀.₅ 能在训练中未见过的新家庭里执行这类长时程、多阶段任务 | 9.18 问题记录 |
| Generalist robot manipulation policies | 通用机器人操作策略 | 一个策略不是只做一个任务 / 物体 / 场景，而是能处理多种任务、物体、环境。传统做法是「一个任务训练一个策略」；generalist policy 希望一个策略就能抓盘子、开抽屉、叠衣服 | 9.21 问题记录 |
| fine-tuning pre-trained | 微调预训练模型 | 先在大而通用的数据上预训练学到通用知识，再在目标任务 / 目标机器人数据上继续训练以适配。VLA 通常先基于预训练 VLM，再用机器人动作数据微调 | 9.21 问题记录 |
| highly expressive action decoding mechanisms | 高表达能力动作解码机制 | 机器人动作连续、多峰、精细（同一任务可有多种抓法，动作序列也很平滑）。解码器太简单只能输出单一、平均化的动作。高表达能力解码器能表示复杂动作分布，常见有 diffusion、flow matching 及高级动作 tokenization | 9.21 问题记录 |
| diffusion | 扩散模型 | 训练时不断给真实数据加噪声、让模型学会去噪；推理时从纯噪声开始一步步去噪生成数据。能表示多模态动作分布（如绕过障碍的多种路径），但推理通常需要多步去噪、可能较慢 | 9.21 问题记录 |
| advanced action tokenization schemes | 高级动作 tokenization | 把连续机器人动作变成离散 token 的方法。简单量化会损失精度；高级方案会压缩动作序列、保留时间结构，让动作能像文本一样被 Transformer 自回归预测 | 9.21 问题记录 |
| Non-robot data co-training | 非机器人数据共训练 | 把机器人数据与非机器人数据混合训练同一个模型。后者（Web 图像描述、视觉问答、物体检测、语言指令）没有动作，但提供物体语义、场景常识与开放词汇知识。π₀.₅ 的共训练配方含 Web 数据 WD 与高层子任务数据 HL | 9.21 问题记录 |
| initialize vision encoders | 初始化视觉编码器 | 视觉编码器把图像变成特征向量（ViT / CLIP 视觉部分）。机器人数据通常很少，所以常见做法是先用大规模 CV 数据预训练编码器，再把权重迁移到机器人策略中。π₀.₅ 的 VLM 主干初始化自 PaliGemma | 9.21 问题记录 |
| off-the-shelf task planners | 现成的任务规划器 | 不专门为当前机器人训练、直接拿来用的高层规划模块（如用 GPT-4 / LLM / VLM 把「清理厨房」分解成「拿起盘子」「放进水槽」）。π₀.₅ 的不同点：不用独立 planner，而用同一个 VLA 同时做高层子任务预测与低层动作生成；论文比较过 GPT-4 作为高层策略的 baseline，效果不如 π₀.₅ 自己学的高层推理 | 9.21 问题记录 |
