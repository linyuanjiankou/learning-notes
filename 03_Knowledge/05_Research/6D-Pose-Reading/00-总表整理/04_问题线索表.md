| **遮挡 vs 自遮挡**（两个不同的东西） | [BOP](../01-笔记/BOP-Benchmark%20for%206D%20Object%20Pose%20Estimation.md)、[MR6D](../01-笔记/MR6D-Benchmarking%206D%20Pose%20Estimation%20for%20Mobile%20Robots.md) | BOP：用 VSD / ADD-S 这类**位姿歧义感知**的指标把遮挡影响量化出来；MR6D：把自遮挡作为数据集的**显式设定**（专项场景覆盖） | 极端/严重自遮挡下仍不稳定。区分点：普通遮挡 = **别的物体挡住目标**；自遮挡 = **目标自己挡住自己**（见 9.26 术语卡）。MR6D 只保证数据集覆盖了自遮挡，**没有提出解法** |
| **2D 分割 → 位姿 的误差传播** | [MR6D](../01-笔记/MR6D-Benchmarking%206D%20Pose%20Estimation%20for%20Mobile%20Robots.md) | 用 GT mask 与 CTL mask 两条 pipeline 对比，把分割这一环单独隔离出来看影响 | **分割质量是 unseen pipeline 的主要瓶颈**，但「分割误差多大 → 位姿误差多大」没有定量关系；SAM 还容易**过分割**，把物体切成很多小块，反而不利于后续位姿估计 |
| **变化光照** | [BOP](../01-笔记/BOP-Benchmark%20for%206D%20Object%20Pose%20Estimation.md) | 靠数据补：新增 TUD-L、TYO-L 两个变化光照数据集；同时观察到一个规律——**只用深度信息的方法更鲁棒** | 依赖合成 RGB 训练的方法在真实光照变化下明显脆弱；这条「深度 > RGB」的规律是观察结论，**没有给出机制解释** |
| **位姿歧义（对称 / 相似物体）** | [BOP](../01-笔记/BOP-Benchmark%20for%206D%20Object%20Pose%20Estimation.md) | 指标层面用 ADD-S、VSD 缓解 | BOP 明确把对称性、物体相似性列为**开放问题**；指标只是「不惩罚」歧义，不等于「解决」歧义 |
| **评测可比性** | [BOP](../01-笔记/BOP-Benchmark%20for%206D%20Object%20Pose%20Estimation.md)、[MR6D](../01-笔记/MR6D-Benchmarking%206D%20Pose%20Estimation%20for%20Mobile%20Robots.md) | BOP 给统一格式 / 统一任务 / 统一指标 + 在线榜单；MR6D 直接沿用 BOP 指标 | 非 BOP 系数据集的工作仍需人工对齐口径；BOP 的结论**基于 2018 年前的方法**，2024 之后的基础模型路线尚未进入这张榜单，结论时效性存疑 |
| **场景假设过窄** | [BOP](../01-笔记/BOP-Benchmark%20for%206D%20Object%20Pose%20Estimation.md)、[MR6D](../01-笔记/MR6D-Benchmarking%206D%20Pose%20Estimation%20for%20Mobile%20Robots.md) | MR6D 把场景从「固定机械臂 + 小型家用物品」换到「移动机器人 + 工业大型物体」 | MR6D 的实用场景其实**接触的都是高确定性物品**（不同于需要高泛化性的开放场景）——这个假设让它的结论不能直接外推到开放世界 |
| **无训练集 / 数据规模** | [MR6D](../01-笔记/MR6D-Benchmarking%206D%20Pose%20Estimation%20for%20Mobile%20Robots.md) | — | MR6D 定位为**评测基准**，没有专门训练集，规模和对象覆盖有限 |

## 本表的使用方式

- 每读一篇新论文，先问一句：**它挂了上面哪一条？**挂不上就新建一行。
- 一行里如果「尚未解决」被填实了，说明这条线已经有人推进 → 去跟进那篇论文。
- 行数超过 10 条时，回头合并相似项——这张表的目的是**看见收敛**，不是越全越好。
